# 대리 결재와 긴급 재배정

## 사용자 위임

결재함의 **대리 결재 설정**에서 그룹, 기간, 대리 결재자와 적용 범위를 지정한다. 대리자는 같은 그룹에 속한 활성 PXM 사용자만 선택할 수 있다. 외부 이메일 주소나 서비스 계정에는 위임할 수 없다.

- 기본 범위는 그룹의 모든 워크플로우이며 필요한 경우 일부 워크플로우만 선택한다.
- `현재 미결 결재도 함께 위임`은 기본적으로 꺼져 있다. 끄면 위임 시작 시각 이후 만들어진 결재에만 적용한다.
- 기간이 끝나거나 위임을 해제하면 처리하지 않은 결재는 원래 승인자의 결재함으로 즉시 돌아간다.
- 같은 사용자와 그룹에 기간이 겹치는 위임은 만들 수 없다.
- 사용자는 자신의 위임을 설정한다. 그룹 관리자는 소속 구성원을, 최고관리자는 모든 구성원을 대신해 설정할 수 있으며 대신 설정할 때는 사유가 필수다.
- 설정과 해제는 감사 로그에 남고 원래 승인자에게 이메일로 알린다. SMTP가 구성되지 않았거나 발송에 실패해도 위임 저장 자체는 유지된다.

위임은 Task의 원래 `assignee`를 바꾸지 않고 유효 기간 동안 실제 처리 권한과 알림 수신자를 대리자에게 전환한다. 따라서 만료 복구 작업 없이도 원래 승인자에게 돌아가며, 동시에 승인·반려가 들어와도 Task 완료의 원자적 갱신으로 한 번만 처리된다. 완료 이력에는 위임 ID, 원래 승인자와 실제 처리자를 함께 저장한다.

Approval 노드의 **대리 결재 허용**을 끄면 해당 노드에서 생성된 Task에는 사용자 위임을 적용하지 않는다. 민감한 결재에 사용한다.

## 관리자 긴급 재배정

예정하지 못한 부재에는 그룹 관리자나 최고관리자가 결재함의 대리 결재 패널에서 특정 미결 결재의 담당자를 직접 바꿀 수 있다. 새 담당자는 같은 그룹의 활성 PXM 사용자여야 하며 사유가 필수다.

긴급 재배정은 기간 위임과 달리 자동 복귀하지 않는다. 이전 담당자, 새 담당자, 수행 관리자, 사유와 시각을 Task와 감사 로그에 기록한다.

## API

- `GET /api/authz/approval-delegations`
- `POST /api/authz/approval-delegations`
- `DELETE /api/authz/approval-delegations/:id`
- `GET /api/authz/approval-delegation-candidates?groupId=...`
- `GET /api/authz/approval-delegations-preview?groupId=...`
- `POST /api/tasks/:id/reassign`
