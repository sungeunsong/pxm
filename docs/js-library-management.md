# JS 라이브러리 관리

PXM-49. JS 노드는 임의 `require`/`import`나 실행 중 `npm install`을 허용하지 않는다. 플랫폼 관리자가 정확한 npm 버전을 준비하고 승인하면 워크플로우 설계자가 해당 버전을 선택해 재사용한다.

## 등록과 승인

최고관리자는 **플랫폼 설정 → JS 라이브러리**에서 패키지 이름과 정확한 버전을 입력한다. **최신 버전**을 누르면 npm 레지스트리의 `latest` 태그를 조회해 현재의 정확한 버전을 자동으로 채운다. 저장되는 값은 `latest`가 아니라 조회 시점의 고정 버전이다.

```text
lodash
4.17.21
```

API는 설정된 npm registry에서 패키지를 내려받는다. 기본 registry는 `https://registry.npmjs.org`이며 `PXM_NPM_REGISTRY_URL`로 Nexus나 Artifactory 같은 사내 registry를 지정할 수 있다. 다운로드 과정에서는 lifecycle script를 실행하지 않는다.

다운로드한 패키지와 운영 의존성은 브라우저용 CommonJS 단일 파일로 묶는다. Node.js 내장 모듈에 의존하거나 브라우저용으로 묶을 수 없는 패키지는 준비 단계에서 거절한다. 번들은 2MB 이하만 허용하며 npm integrity, package lock 해시와 번들 SHA-256을 저장한다.

준비된 버전은 바로 사용할 수 없다. 관리자가 모든 그룹 또는 선택한 그룹에 사용을 승인해야 한다. 같은 패키지의 다른 버전은 별도 항목으로 준비하고 승인한다.

사용 중지는 새로 저장하거나 배포하는 워크플로우에 적용한다. 이미 배포된 워크플로우 버전은 재현성을 위해 포함된 번들을 계속 사용한다. 즉시 실행까지 막아야 하는 보안 사고에는 해당 워크플로우도 함께 비활성화한다.

## 워크플로우에서 사용

JS 노드의 **승인된 라이브러리**에서 사용할 버전을 선택한다. 코드에서는 패키지 이름으로 접근한다.

```javascript
const _ = libs['lodash'];
return {
  total: _.sum([10, 20, 12]),
};
```

워크플로우를 저장할 때 다음을 검사한다.

- 등록된 정확한 버전인지
- 현재 승인 상태인지
- 워크플로우 소유 그룹에 허용됐는지

승인된 번들의 실행 복사본은 워크플로우 버전에 포함된다. 설계 조회, export와 실행 조회 응답에서는 내부 번들을 제거하고 패키지 이름과 버전만 보여준다. Export의 `script_library_dependencies`에서 필요한 버전을 확인할 수 있다.

## 실행 제한

- JS 노드와 라이브러리에 `require`, `import`, `process`, `eval`, `Function`을 제공하지 않는다.
- 번들 SHA-256이 등록 시점과 다르면 실행하지 않는다.
- Node 자식 프로세스는 64MB 힙 제한으로 실행한다.
- 기존 JS timeout과 console 제한을 동일하게 적용한다.
- 파일, DB, HTTP처럼 외부 시스템 접근이 필요한 코드는 JS 라이브러리가 아닌 승인된 플러그인으로 구현한다.

`node:vm` 자체는 강한 보안 경계가 아니다. 따라서 출처를 신뢰할 수 없는 패키지를 승인해서는 안 된다. 다중 고객 운영 환경에서 제3자 코드를 받아야 한다면 Script Runner를 별도 컨테이너로 분리하고 OS 수준 파일·네트워크·CPU 제한을 추가해야 한다.

## 운영 환경 변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PXM_NPM_REGISTRY_URL` | `https://registry.npmjs.org` | 패키지를 받을 npm registry |
| `PXM_NPM_EXECUTABLE` | `npm` | 준비 작업에 사용할 npm 실행 파일 |

패키지는 API가 준비할 때만 외부 registry에서 받는다. Engine 실행 시에는 외부 registry나 인터넷에 연결하지 않는다.
